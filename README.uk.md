# UFO Tech AI skills

[English](README.md) · **Українська**

Скіли й правила для ШІ-агентів, що пишуть код: Claude Code, Codex, Cursor, GitHub Copilot і будь-якого агента, що читає `AGENTS.md`. Опубліковані в каталозі UFO Tech **«Прокачай свій ШІ»**: https://ufo-tech.space/uk/ai

Каталог читає цей репозиторій і показує кожну позицію на окремій сторінці: опис, файли для кожного агента, команди встановлення. Для агентів він віддає індекс у машинному форматі, тож агент може сам знайти й встановити потрібну позицію.

## Склад

### Скіли

Скіл — це задача, яку агент виконує сам, коли вона доречна: робочий процес, генератор, чек-лист зі скриптами. Встановлюється як тека.

| Позиція | Що робить | Агенти |
|---|---|---|
| [`ufo-tech/ufo-catalog`](ufo-tech.ai/skills/ufo-catalog) | Навчає агента шукати скіли й правила в каталозі UFO Tech і встановлювати їх у проєкт або глобально, з перевіркою контрольних сум. | Claude Code, Codex, будь-який агент за посиланням |
| [`ufo-tech/develop-folder`](ufo-tech.ai/skills/develop-folder) | Створює й веде в проєкті папку `.develop`: глосарій, дослідження, відкриті питання з рішеннями, задачі, готові до Jira, і опис того, як працює система. | Claude Code, Codex |
| [`ufo-tech/ufo-skill-author`](ufo-tech.ai/skills/ufo-skill-author) | Допомагає створити скіл чи правило для каталогу: структура, `manifest.yaml`, README, варіанти для різних агентів і спільні файли без дублювання. | Claude Code, Codex |

### Правила

Правило — це інструкції, яких агент дотримується в проєкті завжди: як працювати з бібліотекою, якого стилю коду триматися. Встановлюється як один markdown-файл, на який посилаються `CLAUDE.md`, `AGENTS.md`, налаштування Cursor чи Copilot.

| Позиція | Що робить |
|---|---|
| [`ufo-tech/json-rpc-bundle`](ufo-tech.ai/rules/json-rpc-bundle) | Як агенту працювати з `ufo-tech/json-rpc-bundle`: процедури, параметри, результати, помилки, кеш, версії й групи API, події, відомі пастки й перевірка результату. |
| [`ufo-tech/json-rpc-bundle-extensions`](ufo-tech.ai/rules/json-rpc-bundle-extensions) | Для пакетів, що розширюють бандл (транспорти, адаптери протоколів, інтеграції): точка входу через `RpcExecutor`, токени, групи й версії, маршрути, вимоги до пакета. |
| [`ufo-tech/ufo-code-style`](ufo-tech.ai/rules/ufo-code-style) | Необов'язковий стиль коду команди UFO-Tech для PHP: типізація, DTO, тонкі контролери, сервіси, ранні повернення. |

У теці кожної позиції є свій `README.<locale>.md` з подробицями: коли спрацьовує, що потрібно, які кроки налаштування зробити вручну.

## Встановлення

**Зі сторінки каталогу.** Відкрийте позицію на https://ufo-tech.space/uk/ai, оберіть агента й місце встановлення (цей проєкт чи глобально) і виконайте показані команди. Кожен файл звіряється з його SHA-256 з індексу.

**Попросити агента.** Один раз встановіть скіл `ufo-tech/ufo-catalog` (або дайте будь-якому агенту посилання https://ufo-tech.space/ai/install.md), а далі просіть звичайними словами, наприклад:

> встанови скіл develop-folder з каталогу UFO Tech глобально

Агент показує, що і куди завантажить, звіряє контрольні суми й без вашого дозволу не запускає завантажені скрипти та не змінює глобальні налаштування.

**Вручну.** Скопіюйте теку варіанта для свого агента і додайте в неї вміст `shared/`. Якщо шлях збігається, перемагає файл варіанта.

| Агент | Скіл у проєкті | Скіл глобально |
|---|---|---|
| Claude Code | `.claude/skills/<name>/` | `~/.claude/skills/<name>/` |
| Codex | `.agents/skills/<name>/` | `~/.agents/skills/<name>/` |

`<name>` — частина назви позиції після `/`, наприклад `develop-folder`. Правило — це один файл з `universal/`: покладіть його в проєкт і пошліться на нього з `CLAUDE.md`, `AGENTS.md`, `.cursor/rules/` або `.github/copilot-instructions.md`.

## Структура репозиторію

Каталог читає лише теку `ufo-tech.ai/`. Вкладеність усередині може бути будь-якою: сканер проходить кожну гілку й зупиняється на першій теці, де є `manifest.yaml`. Ця тека і є позицією.

```
ufo-tech.ai/
├── skills/
│   └── develop-folder/
│       ├── manifest.yaml        # назва, тип, заголовки, описи, автори, підтримка, теги
│       ├── README.en.md         # обов'язковий
│       ├── README.uk.md         # за бажанням, по файлу на кожну додаткову мову
│       ├── claude/SKILL.md      # варіант для Claude Code
│       ├── codex/SKILL.md       # варіант для Codex
│       └── shared/              # файли, що додаються в кожен варіант (скрипти, шаблони, довідка)
└── rules/
    └── ufo-code-style/
        ├── manifest.yaml
        ├── README.en.md
        ├── README.uk.md
        └── universal/ufo-code-style.md   # саме правило, один файл для всіх агентів
```

- **Теки варіантів** названі за агентом: `claude`, `codex`. `universal` — один варіант для всіх агентів (у правил) або версія, яку читають за посиланням (у скілів).
- **`shared/`** зберігає спільні файли один раз, у варіантах лише те, що відрізняється.
- **Обов'язково для позиції:** валідний `manifest.yaml`, хоча б одна тека варіанта, `SKILL.md` у кожному варіанті скіла (у варіанті правила — хоча б один `.md`) і `README.en.md`. Позицію, якій чогось бракує, каталог пропускає, а решта позицій публікується.

## manifest.yaml

```yaml
version: 1.0                      # версія формату маніфесту
name: ufo-tech/develop-folder     # vendor/name, латиниця в kebab-case; після публікації не змінюється
type: skill                       # skill | rule
title:
    en: The .develop working folder        # англійська обов'язкова
    uk: Робоча папка .develop              # інші мови — за бажанням
summary:
    en: Creates and maintains a project's .develop folder — …
    uk: Створює й веде в проєкті папку .develop — …
authors:                          # як у composer.json
    - name: Ashterix
      email: you@example.com      # необов'язково; ніде не показується, лише для зв'язку й ідентифікації
support:                          # як у composer.json
    source: https://github.com/UFO-Tech/ai-skills
    issues: https://github.com/UFO-Tech/ai-skills/issues
tags: [ai-workflow, documentation]
```

**Версії.** Поля версії в позиції немає. Її версія — це дата й короткий хеш останнього коміту, що змінив файл у її теці, у форматі `YYYY.MM.DD.<hash>` (наприклад, `2026.10.23.1a2b3c4`). Посилання для встановлення ведуть саме на цей коміт, тож агент отримує ті самі файли, що показує каталог.

Повна специфікація, зокрема як писати `SKILL.md` і правила, — у [`ufo-skill-author/shared/reference.md`](ufo-tech.ai/skills/ufo-skill-author/shared/reference.md).

## Участь

- **Помилки та ідеї** щодо позицій цього репозиторію — в [issues](https://github.com/UFO-Tech/ai-skills/issues).
- **Зміни** — через pull request. Тримайтеся структури, описаної вище, оновлюйте обидва README позиції, давайте скрипти у двох версіях, `.sh` і `.ps1`, з однаковою поведінкою. У жодному файлі не має бути секретів, токенів, внутрішніх адрес чи персональних даних.

## Як опублікувати свої скіли й правила

Каталог приймає позиції з будь-якого публічного репозиторію на GitHub із тією самою структурою `ufo-tech.ai/`:

1. **Зберіть теку позиції** в `ufo-tech.ai/` свого репозиторію. Це зробить за вас скіл `ufo-tech/ufo-skill-author`. У `name` вкажіть власний vendor, наприклад `acme/my-skill`.
2. **Увійдіть** на https://ufo-tech.space через GitHub-акаунт.
3. **Встановіть GitHub App каталогу** на репозиторії, які хочете опублікувати. Застосунок отримує доступ до їхнього вмісту лише на читання.
4. **Зробіть push.** Каталог прочитає репозиторій одразу, а далі перечитуватиме після кожного push. Позиції з'являються в каталозі, щойно їхні маніфести й обов'язкові файли валідні. Пропущені позиції разом із причиною видно у вашому кабінеті на сайті.

**Vendor.** Vendor належить GitHub-акаунту, який першим опублікував позицію з ним. Інших мейнтейнерів, наприклад колег з тієї ж організації, додає наявний мейнтейнер у кабінеті на сайті. Позицію з чужим vendor не буде прийнято.

**Оцінки й скарги.** Відвідувачі, що увійшли на сайт, можуть поставити позиції лайк чи дизлайк і поскаржитися на неї. Позиція зі скаргою лишається в каталозі з позначкою «на перевірці», її переглядає модератор. Позицію, на яку поскаржилися як на шкідливу, приховують до завершення перевірки.
