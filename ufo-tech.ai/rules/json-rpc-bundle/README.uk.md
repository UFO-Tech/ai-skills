# Правила для JsonRpcBundle

Файл інструкцій для проєктів, що надають API через [JsonRpcBundle](/docs/api/json-rpc-bundle). Він підключається поруч із вашими правилами й не замінює ваш `AGENTS.md` чи `CLAUDE.md`. Написано англійською, бо асистенти стабільніше виконують англомовні інструкції; версія бандла — **10.4**.

## Що всередині

**Як агенту працювати** — на початку файлу:

* джерело правди — встановлений код бандла у `vendor/` і описи релізів у `vendor/ufo-tech/json-rpc-bundle/releases/`, а не пам'ять моделі;
* перевіряти встановлену версію; не вигадувати класи, атрибути, опції; про суперечність правил і коду — повідомляти;
* не змінювати публічні RPC-контракти без потреби (несумісні зміни — нова версія API) і не рефакторити поза задачею.

**Правила бібліотеки** — коротко, з посиланнями на документацію замість пояснень: тонкі процедури, DTO і декларативна валідація, формат результату, помилки, кеш, версії та групи API, події.

**Відомі пастки 10.4** — застарілі атрибути й події, `#[RPC\DTOCollection]` на методі, `ttl` для `#[RPC\Lock]`, особливості подій для Messenger і помилок HTTP (див. [Актуальні помилки](/docs/api/json-rpc-bundle/developers/known_issues/open)).

**Перевірка перед завершенням** — тести, виклик зміненого методу, схема в `GET /rpc`.

:::info subtitle="Чому це не документація"
Файл навмисно не пояснює, як працюють механізми, — для цього є документація, на яку він посилається. Так інструкція лишається короткою і не перетворюється на другу копію документації, яка з часом розійдеться з першою.
:::
